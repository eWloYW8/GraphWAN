# WireGuard access

A WireGuard node is a leaf of a GraphWAN Network. It has its own virtual address
and exactly one Edge to a regular Agent node. The Agent terminates standard
WireGuard and routes its IP packets through the configured GraphWAN topology.
Other nodes can reach the client through that Agent; no overlay SNAT is used.
WireGuard nodes cannot connect to each other directly, forward transit traffic,
or advertise external subnets. Multiple clients can share one access Agent.

## Add a client

1. Upgrade the Server and Agents, open a Network and enter edit mode.
2. Choose **Add node → WireGuard**, choose an access node and a virtual address.
   The panel suggests an unused address and creates the single attachment Edge.
3. Generate a client key in the browser, or paste a public key generated by your
   WireGuard client. Save the Network.
4. Open the WireGuard node. Once its Agent reports the access public key,
   download the configuration or display the QR code and import it into WireGuard.

The client private key stays in browser memory, never in topology, API requests,
localStorage or Server storage. Download before closing/reloading the page.
Only its public key is persisted and replicated. For a supplied public key,
export a template and add your private key locally; alternatively paste that
private key into the local-only field to generate a complete config/QR code.
Generating a new key while editing takes effect on Save and revokes the old key.

Each Agent derives a separate X25519 key per Network from its locally persisted
identity seed using HKDF-SHA256 and a dedicated domain separator. Private keys
are never sent to the Server; public keys are reported by the Agent. They survive
restarts and ordinary configuration refreshes. Re-enrolling with a new identity,
changing the access Agent or recreating the Network changes the access key and
requires updating the client configuration.

## Entry point and client routes

The **Endpoint override** is a client-facing UDP `host:port`, `IPv4:port` or
`[IPv6]:port`, not the client's listening address. It may point to a port mapping
or UDP forwarder. Leaving it empty selects an unexpired UDP endpoint from the
access Agent, preferring public STUN observations, then public interface addresses.
A manual value is never overwritten by discovery.

The UDP entry point must actually be reachable from the client. Discovering a
STUN mapping does not guarantee unsolicited inbound traffic works through NAT.
The access Agent may use any supported GraphWAN transport for subsequent hops.
Plain WireGuard clients do not support GraphWAN TCP/WebSocket/gRPC tunnelling.

Exports default to the Network CIDR in `AllowedIPs`, MTU at most 1280 and
`PersistentKeepalive = 25`. Keepalive is configurable, including zero. Including
advertised subnets is optional; their gateway forwarding/return path must already
be configured. No default internet exit, DNS override or host routes on other
GraphWAN nodes are created by this feature. Native WireGuard clients do not
receive controller updates: re-export/re-import after endpoint, key, address or
client route changes. Config files and QR codes contain the client private key.

## Runtime and status

WireGuard shares the Agent UDP port with native GraphWAN UDP, STUN and QUIC.
An embedded official wireguard-go engine handles encryption, roaming, rekeys,
replay protection and cryptokey routing. A bounded in-memory packet adapter
connects it to GraphWAN; no extra OS WireGuard interface or executable is needed
on the Agent. Per-Network devices isolate peer sets and keys; existing constraints
still forbid overlapping Networks on the same Agent.

The access Agent enforces each peer's assigned /32 or /128 source address.
GraphWAN preserves that node identity through multi-hop forwarding and applies
its existing live route/MTU checks. The access Agent can see plaintext between
the WireGuard and GraphWAN encryption layers, as any terminating VPN gateway can.

Telemetry includes the latest handshake, client endpoint and byte counters.
An enabled attachment is routable while the Agent reports a handshake within
three minutes. Before a handshake the panel shows Waiting; after expiry it shows
Idle, which does not prove the client is offline. Default keepalive maintains
NAT reachability and refreshes sessions. WireGuard RTT is not measured and should
not be interpreted as zero latency. A fresh handshake restores the live route
on the following Agent report. Routes through failed ordinary Edges remain excluded.
Disabling the Edge removes the admitted WireGuard peer. Removing an access node
also removes its attached WireGuard nodes. Normal endpoint/position/name updates
do not reset sessions; changes to the peer set, addresses or MTU may reinitialize
the affected Network's WireGuard device.

Verification targets Linux. Windows/macOS builds use the same userspace adapters;
native acceptance on those platforms is not claimed.
